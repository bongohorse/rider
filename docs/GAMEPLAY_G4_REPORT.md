## Behavior and authoring

The existing editor's top-bar **Coin** tool places ordinary coins on the current grid. Select [S] and drag to move; Copy/Paste duplicates; Delete removes; Undo/Redo, autosave/My levels, snapshots and Export/Import use the existing object workflow. Each source coin has an ordinary editor object ID and a stable `pickup_id`. Moves/save/reload/Undo preserve that pickup ID; pasted/mirrored copies allocate fresh IDs, including collision checks against imported IDs. Source and compiled validators reject duplicates, nonfinite/outside-bounds positions, unknown versions/fields and more than 128 coins. The source format is editor/compiler 9; compiled coin-bearing levels use station schema 2, with a version-1 ordinary coin list. Coin-free levels keep station schema 1. Older runtimes therefore refuse coin-bearing exports instead of silently ignoring gameplay pickups. Versions 1–8 source upgrade without adding coins or changing existing geometry, medal targets or Terrain Look.

The first-run course has nine accessible coins at x = 12, 25, 40, 60, 80, 100, 120, 140 and 155 m, each 0.7 m above the sampled road. These are provisional drive-test positions. A coin is worth one. HUD shows collected/available, a short +N pickup acknowledgement and the acknowledged bank total. Collected sprites disappear immediately. Finish shows the attempt's haul and bank/save state alongside time/medal/next target. Practice results are explicitly unbanked; a failed attempt's haul is lost. Retry restores the same Sprite objects, clears collected IDs, previous sweep positions and feedback/count; it never resets the durable bank.

## Authority and banking

The existing controller fixed tick is the only pickup owner. After reading the completed vehicle step and evaluating failure, it samples conservative chassis-centre radius 0.65 m, the existing rotated head sensor centre/radius and the two wheel centres/radii (0.22 m). The pickup radius is 0.25 m. Point-to-segment distance tests sweep those observed centres from the preceding tick, so fast crossings need no physics sensor or manual world step. A per-attempt stable-ID set accepts one pickup even when several parts overlap or the car reverses through it. Pause/ready/failed/finished never collect; ready observations update the reference without awarding. Canonical Retry drops the old reference so teleports cannot sweep through coins. Finish is still the existing directed chassis crossing, never coin count or route percentage; same-tick pickups are evaluated before that crossing. Visual feedback does not own collection or time.

Only the authoritative run's frozen official terminal result submits a credit. Existing eligibility remains shipped course, intended unmodified vehicle/preset A, crash enabled, zero start speed, time factor 1, no editor/import/template/debug/test/replay. The loader verifies sender and current world generation. A monotonic attempt cursor within that generation rejects repeated/stale/reclassified results, including zero/practice offers. New valid attempts may earn the same course coins again. Failed, abandoned and restarted attempts submit no haul. There is no attempt resume after reload.

One explicit loader-owned bank survives world/Edit/Play switches. It stores `{version=1,total,serial}` in the existing alternating-slot wrapper (`coin-bank-a/b`). Total and serial are nonnegative integers capped at 2147483647. The record contains an **absolute cumulative total**, not a replayable delta. One in-flight immutable snapshot serializes writes; new legitimate finish amounts queue into the desired total until that snapshot is acknowledged. Duplicate events do not add a desired amount again. A failed file write retries the same snapshot at most three times, one second apart, without adding its amount again. A browser sync failure stops writes and shows Coins not saved. No balance increase is published before the existing HTML5 IndexedDB acknowledgement; reload restores the last persisted snapshot without resubmitting an old result. A valid surviving slot remains readable while any unreadable/corrupt/future alternate protects both from overwrite. Storage is single-tab, matching the existing editor storage contract; no accounts or multi-client ledger are introduced.

The bank is global to the local game save and independent of level/competition revision, best time and medal storage. Target/Terrain Look edits do not affect it. Adding/moving optional ordinary coins does not change the existing best/medal competition namespace, vehicle, physics or valid finish rules. Physics/start/finish revision policy remains the medal policy. There is no spending, shop, upgrade, special coin or fuel system in this slice.

## Resources and compatibility

Each ordinary coin is one shared-atlas Sprite and one GameObject, with no collision object, body, shape, joint or per-coin script/update loop. Art is Rider-owned circle/rectangle SVG rasterized with the existing `tools.art.wheel.raster` development helper; no runtime library or asset dependency is added. The current terrain admission counts coin Sprites/instances and editor old/new replacement headroom. Pools, sampling and physical terrain remain unchanged. The retained editor draws and moves individual sprites in place; deleted/replaced owners use the existing deferred-deletion bookkeeping. Runtime Retry toggles the existing coin sprites and clears instance-owned collection data; world unload owns their destruction. The result/HUD reuse two fixed native text nodes and the existing mobile readout. Terrain Look supports known source versions 7/8/9; the stale version-7-only contract reference noted in #299's review is aligned here.
