# Android platform and engine boundary findings

The supplied Android launch path uses `AppActivity` and the Cocos2dx Java integration. Input, rendering and several lifecycle operations cross JNI into native code; the Java sources support a platform-boundary description, not a reconstruction of driving physics or replay/network algorithms. All findings below are static. The claim ledger records source hashes, exact locators, confidence and limitations.

## Startup and native loading

**AND-001.** The manifest declares androidx.multidex.MultiDexApplication as Application, com.fingersoft.hcr2.AppActivity as the game activity, and cocos2dcpp as android.app.lib_name. Manifest configuration is static evidence; it is not an observed launch trace. Evidence: [AndroidManifest.xml](/workspace/HC2/decompiled/android/apktool/base/AndroidManifest.xml:94).

**AND-002.** MultiDexApplication extends nmokwhs.ab. attachBaseContext calls its superclass, CrashpadLoader.onAttachBaseContext, then MultiDex.install. Its class initializer calls nmokwhs.d.b(). Native callbacks and class initialization side effects can add behavior beyond this explicit Dalvik sequence. Evidence: [MultiDexApplication.smali](/workspace/HC2/decompiled/android/dex/base_classes_03/smali/androidx/multidex/MultiDexApplication.smali:1), [MultiDexApplication.java](/workspace/HC2/decompiled/android/jadx/base_classes_03/sources/androidx/multidex/MultiDexApplication.java:8).

**AND-003.** nmokwhs.d.c() calls W.c(), then d.d(); d.d explicitly calls System.loadLibrary("fingersoft_hcr2"). The superclass nmokwhs.ab class initializer calls d.b(). This establishes a Java-driven bootstrap path, not a complete native dependency order or proof of what the native initializer does. Evidence: [d.smali](/workspace/HC2/decompiled/android/dex/base_classes_02/smali/nmokwhs/d.smali:172), [ab.smali](/workspace/HC2/decompiled/android/dex/base_classes_01/smali/nmokwhs/ab.smali:7), [d.smali](/workspace/HC2/decompiled/android/dex/base_classes_02/smali/nmokwhs/d.smali:37).

**AND-004.** CrashpadLoader loads bts and initializes its hookable library list with backtrace-native and crashlytics-common. Its onAttachBaseContext initializes the native library directory and attempts to load the listed libraries. Loading attempts catch UnsatisfiedLinkError; these sources do not prove successful initialization on a device. No explicit wtp load is established by this inspected chain. Evidence: [CrashpadLoader.smali](/workspace/HC2/decompiled/android/dex/base_classes_01/smali/no/promon/backtrace_support/CrashpadLoader.smali:19), [CrashpadLoader.smali](/workspace/HC2/decompiled/android/dex/base_classes_01/smali/no/promon/backtrace_support/CrashpadLoader.smali:69).

## Rendering and input

**AND-006.** The activity builds a Cocos2dxGLSurfaceView, installs Cocos2dxRenderer, and calls onLoadNativeLibraries during onCreate. onLoadNativeLibraries reads android.app.lib_name and calls CrashpadLoader.loadLibrary. This proves Cocos2dx-style Java integration on the launch path, not an exact upstream Cocos2d-x version or an unmodified engine. Evidence: [Cocos2dxActivity.java](/workspace/HC2/decompiled/android/jadx/base_classes_02/sources/org/cocos2dx/lib/Cocos2dxActivity.java:131), [Cocos2dxActivity.java](/workspace/HC2/decompiled/android/jadx/base_classes_02/sources/org/cocos2dx/lib/Cocos2dxActivity.java:203).

**AND-007.** The GL view requests an EGL client context version of 2 and uses the custom FSGLSurfaceView layer. A requested context version does not establish every native graphics feature, extension, backend, or shader version used. Evidence: [Cocos2dxGLSurfaceView.java](/workspace/HC2/decompiled/android/jadx/base_classes_02/sources/org/cocos2dx/lib/Cocos2dxGLSurfaceView.java:133), [Cocos2dxGLSurfaceView.smali](/workspace/HC2/decompiled/android/dex/base_classes_02/smali/org/cocos2dx/lib/Cocos2dxGLSurfaceView.smali:513).

The Java renderer keeps a default 16,666,666 ns animation interval, supports changing it, and can sleep when a longer interval is configured. This is render-callback pacing. It does not prove the native physics timestep, deterministic simulation, frame-to-tick ratio, or replay determinism.
