# Automation provenance and release boundary

Use [bridge.md](bridge.md) for pinned source/wrapper identity, native capability evidence and unresolved license provenance. G2 completion is historical evidence; no repeated G2 implementation gate is imposed by this contract.

Preserve capability verification on a named supported native debug platform: identify the owned process/project/run, compare actual extension/wrapper versions and required capabilities, inspect a known element/state, send input and observe its actual effect (HTTP success/receipt alone is insufficient), and capture a completed screenshot on promised graphics platforms. Explicitly record unsupported headless/other-platform capabilities. Native evidence does not replace HTML5 or real Android tests.

Install the Python wrapper from the exact pinned extension source; update both together with provenance and actual API/capability checks. Never invoke uncontrolled Latest updates. Missing catalog license metadata is neither a license grant nor proof of a prohibition. The user authorized implementation despite the recorded missing license; this is not an upstream license grant.

Before any app distribution in Phase B, move the Bridge dependency to debug-only settings and prove it is absent from release build dependencies and binary contents, along with no Lua module/debug IDs/listeners. G2's started-release capability-negative test alone does not prove binary exclusion. The existing HTML5 build clears the native dependency; preserve that for A4 preview.

Keep editor/runtime services private; document remote/container access. Review privileged eval before use (none currently invoked). Ignore secrets and redact CI output. Use minimum GitHub permissions and no production secrets for untrusted PRs. See [PLAN.md](../../PLAN.md) for deployment and release scope.
