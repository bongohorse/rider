## Run

Use the pinned environment and loopback Extender from [the local runbook](../../docs/LOCAL_T3_SETUP.md). Set `PATH` to the existing approved Python environment if necessary.

```sh
RIDER_BUILD_SERVER=http://127.0.0.1:9000 python tools/parallax545/build.py --output artifacts/parallax545/build
node tools/parallax545/measure.cjs artifacts/parallax545/build artifacts/parallax545/measurement
python tools/parallax545/analyze.py artifacts/parallax545/measurement
```

Both destinations must be fresh. `RIDER_PYTHON` selects the Python executable for bundle verification. The build uses the existing exact Bob/JDK/engine guards; the observer verifies the input fingerprint, bundle inventory and the bytes of the loaded Wasm engine. Keep sources unchanged between build and measurement.

## Protocol

The observer writes `plan.json` before measuring, including source/engine SHA, browser version, host CPU, viewport (1280×720), DPR (1), matrix and timing. Each matrix entry uses a new browser context, default player settings and the same course. After drive-ready, warm up for 3 seconds, measure idle for 5 seconds, then hold W for 5 seconds using ordinary input. The follow camera supplies the same render-only path for both routes. Frame counts and resulting camera/vehicle telemetry remain in raw evidence; equal elapsed time does not imply equal fixed tick counts under overload.

The matrix is mesh/sprites × 0/3/6 layers, followed by six layers hidden from startup for each route. The sprite grid uses the smallest centered symmetric ring covering the declared camera zoom envelope under modulo scrolling. A per-frame projection assertion refuses camera changes outside that envelope. Layers use distinct 1024×512 RGBA8 images. Meshes draw one repeated-UV quad per layer, with straight-alpha output for the default mesh blend pass; sprites use their built-in premultiplied-alpha blend. UV centers match the sprite tiles. Sprites repeat the same image over a bounded grid, letting Defold batch normally. Both update offsets in X and Y from one fixed per-layer depth. Backgrounds sort before terrain and vehicle; foreground after them; GUI sorts last. This is diagnostic geometry and an experimental depth mapping, not the production Depth contract.

The observer records every frame's browser interval, callback wall time, WebGL draw count and texture order, as well as texture level dimensions and explicit format-aware upload payload. The analyzer recomputes timing statistics from finite, monotonic raw frames and validates memory and draw deltas; it does not automate draw-order acceptance. Inspect screenshots and texture-order traces separately and record that review in the PR. Keep screenshots and raw JSON in ignored artifacts and PR evidence. Do not copy completed reports into repository docs.

## Interpretation

The desktop feasibility screen is **16.67 ms total frame time**; incremental cost is reported separately against each route's zero-layer baseline. Callback time excludes deferred GPU work. Browser intervals include scheduling and are therefore also reported. Software rendering does not establish hardware GPU or phone acceptance. If six layers exceed budget, record the failure and stop for Claudio's decision rather than silently relaxing the threshold or selecting a production route.

Empty and initially hidden layers do not load image resources or create visual objects. The hidden case proves avoidance at startup; it does not prove release after a live visibility toggle. Resource lifecycle and safe-zone product behavior remain production work. No image or art-direction approval follows from these diagnostic fixtures.

## Assets and engine references

All six PNGs are original deterministic diagnostic grids generated by [assets.py](assets.py), using only Python standard-library code and the numeric colors and alpha recipe in that file. They are seamless in both axes and contain no external assets. Regenerate with `python tools/parallax545/assets.py`; inputs have no seed, external file or network dependency. They are test assets, not environment presets (#547).

- [Resource API](https://defold.com/ref/resource/): dynamic buffer ownership and release.
